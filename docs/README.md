## 2. 一条硬规则：改代码必须同步文档

**任何功能新增、字段调整、接口变更、界面改版，都要在同一批提交里更新对应手册；没有对应手册的，新建一份。** 不许出现「代码已上线、文档还停在上个版本」的情况。

这条规则有自动校验兜底：`node scripts/check-docs.js`（`npm run docs:check`）会检查——

1. 每份手册头部的「适用版本」是否等于 `package.json` 的 `version`；
2. README 的「当前版本」是否一致；
3. 文档里的相对链接是否都存在；
4. `public/app.js` 的 `APP_VERSION` 是否等于 `package.json` 的 `version`（前端用它和 `/healthz` 比对，识别「改了没重启」的旧进程）；
5. 是否残留过时的测试数量。

CI 的「文档一致性检查」步骤跑的就是它，**版本号没同步或链接写坏，流水线直接红**。

## 3. 版本号与文档的对应关系

- `package.json` 的 `version` 是唯一版本源；打 tag 时同步改所有文档头部的「适用版本」。
- 纯文档修订也升一个 patch 版本（如 v1.3.2 → v1.3.3），并在 CHANGELOG 里写明「文档同步」，避免文档与代码版本号对不上。

## 4. 写文档的约定

- 事实以代码为准：写完回头 `grep` 一遍函数名/字段名，确认没有写已删除的旧字段（例如 `offPeak` 已在 v1.3.1 更名为 `idle`）。
- 命令、路径、JSON 用代码块；中文叙述用中文标点。
- 涉及时间的规则必须写明时区（本项目统一按**北京时间 UTC+8** 判断峰谷，与服务器时区无关）。
- 涉及金额必须写明币种与单位（本项目统一 **元 / 百万 tokens**，美元价按 `lib/preset-prices.js` 顶部 `USD_CNY` 折算）。
- 不写「即将支持」的假功能；未实现的写进「未实现 / 扩展点」小节。
