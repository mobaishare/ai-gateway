## 1. 用量告警

额度快用完时，平台可以主动推送到飞书或企业微信的群机器人，不用天天盯着管理台。

### 1.1 触发条件

| 告警对象 | 阈值 | 前提 |
| --- | --- | --- |
| 员工**每日** Token 额度 | 80% / 100% | 该员工生效的日额度 > 0（0 表示不限，不告警） |
| 部门**每日** Token 池 | 80% / 100% | 部门日额度 > 0，且该员工「占用部门池」为开 |

只在**记账完成后**检查（`lib/alerts.js` 的 `check()` 由网关在记账后调用）。

不覆盖的维度（当前版本）：月额度、RPM、并发、模型权限越权。这些只能从概览页预警条和调用日志里发现。

### 1.2 防打扰策略

1. **每个对象 × 每个阈值 × 每天只发一次**。去重键为 `emp:<员工id>:<阈值>` / `dept:<部门id>:<阈值>`，存在 `db.stats.alerts.sent` 里。
2. 状态随统计一起落盘（防抖写盘），重启不会重复发；跨天按日期键自动重置。
3. 发送是异步 fire-and-forget，失败**只打服务端日志，不影响也不阻塞**员工请求。
4. 单次发送超时 8 秒（`AbortController`）。

### 1.3 消息格式

飞书自定义机器人：

```json
{ "msg_type": "text", "content": { "text": "【AI API 分流平台】额度预警\n李娜（研发部）今日 Token 已达 82.3%：4,115,000 / 5,000,000" } }
```

企业微信群机器人：

```json
{ "msgtype": "text", "text": { "content": "（同上文本）" } }
```

格式按 URL 自动识别：

| URL 特征 | 判定 |
| --- | --- |
| `open.feishu.cn` 或 `*.larksuite.com` | 飞书 |
| `qyapi.weixin.qq.com` | 企业微信 |
| 其他 | 默认按飞书格式发（HTTP 200 即算成功） |

### 1.4 配置步骤

1. **在群里加机器人**：
   - 飞书：群设置 → 群机器人 → 添加机器人 → 自定义机器人 → 复制 Webhook。
   - 企微：群设置 → 群机器人 → 添加 → 复制 Webhook。
2. 管理台 → **系统设置 → 用量告警** → 粘贴 Webhook → 保持「启用用量告警」开启 → **保存设置**。
3. 点 **「发送测试消息」**，群里应立即收到一条测试消息（该按钮用当前输入框地址发，不要求先保存）。
4. 没收到时，看返回的 `message`：`HTTP 4xx` 多为地址错误、`code=19021` 多为签名校验失败、`超时` 多为出口网络不通。

也可以直接调接口：

```bash
curl -s -X POST localhost:8787/api/settings/test-webhook \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"webhookUrl":"https://open.feishu.cn/open-apis/bot/v2/hook/xxx"}'
# → {"ok":true,"message":"已发送","type":"feishu"}
```

### 1.5 告警排障

| 现象 | 排查 |
| --- | --- |
| 测试消息能收到，但用量超了没告警 | ① 只在**日额度**维度触发，月额度超了不推；② 该阈值当天已发过（`db.stats.alerts.sent` 有记录）；③ 员工日额度为 0（不限） |
| 服务端日志出现 `[alerts] 告警发送失败` | 日志里带 HTTP 状态与响应体片段；常见是 Webhook 被删、机器人被移出群、出口代理不通 |
| 重启后又收到同一条 | 说明上次 `save()` 未落盘就崩溃；正常路径会先落盘再发送 |
| 想换群 | 改 Webhook 地址后保存即可，去重状态不重置（当天不会再补发旧阈值） |

## 2. 日常自检

| 检查项 | 方式 | 正常表现 |
| --- | --- | --- |
| 进程存活 | `curl -s localhost:8787/healthz` | `{"ok":true,...}` |
| 渠道可用 | 渠道页「连通测试」 | `ok: true`，返回耗时 |
| 计费生效 | 概览「今日模型成本」 | 有值的模型即为已定价；`—` 表示未定价 |
| 峰谷状态 | 单价卡右上角徽标 | 与当前北京时间对得上 |
| 数据落盘 | `ls -l data/db.json` | 修改时间随请求增长（有防抖，最多延迟 1 秒左右） |
| 日志积压 | 调用日志页 | 最近记录时间接近当前 |

服务端日志输出到 stdout，systemd 用 `journalctl -u ai-gateway -f`，Docker 用 `docker logs -f ai-gateway`。

## 3. 部署

### 3.1 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；只给本机反代用可设 `127.0.0.1` |
| `GW_DATA_DIR` | `./data` | 数据目录（`db.json` 与备份都在这）；测试与多实例隔离都靠它 |

```bash
PORT=9000 GW_DATA_DIR=/var/lib/ai-gateway node server.js
```

### 3.2 Docker

```bash
docker build -t ai-gateway .
docker run -d --name ai-gateway \
  -p 8787:8787 \
  -v ai-gateway-data:/app/data \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  ai-gateway
```

- 镜像基于 `node:20-alpine`，内置 `HEALTHCHECK`（打 `/healthz`），`VOLUME /app/data`。
- 数据全在 `ai-gateway-data` 卷里，升级镜像 `docker pull`/重建容器不丢数据。
- 建议设 `TZ=Asia/Shanghai`：**日/月统计边界按服务器本地时区切分**，峰谷判定固定用北京时间、不受此项影响。

### 3.3 systemd

```ini
# /etc/systemd/system/ai-gateway.service
[Unit]
Description=AI API Gateway
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/ai-gateway
ExecStart=/usr/bin/node server.js
Environment=PORT=8787
Environment=GW_DATA_DIR=/var/lib/ai-gateway
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now ai-gateway
journalctl -u ai-gateway -f
```

### 3.4 Nginx 反代（流式必看）

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection '';
    proxy_buffering off;          # 必须关，否则 SSE 流式会被缓冲住
    proxy_cache off;
    proxy_read_timeout 300s;
}
```

- 反代层也要放开请求体大小（默认 1M 可能不够长上下文）：`client_max_body_size 8m;`。
- 想限制管理台来源、只对外开放 `/v1/` 时，用两个 `location` 分别控制 `allow/deny`。

### 3.5 CI

`.github/workflows/ci.yml`：推送到 `main` 或开 PR 时触发，做三件事——

1. `node --check` 检查所有 JS 语法（含 `scripts/`）；
2. `node scripts/check-docs.js` 校验文档版本号与链接（见 [docs/README §2](README.md#2-一条硬规则改代码必须同步文档)）；
3. `node test/run.js` 跑端到端测试（临时数据目录 + 独立端口，不碰真实数据）。

徽章在 README 顶部，红了自己点进去看日志。

## 4. 备份、恢复与升级

### 4.1 备份

- **全部数据就是一个文件**：`data/db.json`。停不停服都行，但建议 `cp` 前先 `curl /healthz` 确认在跑（写盘是原子 rename，直接复制不会拿到半个文件）。
- 定时备份示例（crontab，每天 2:00）：

  ```cron
  0 2 * * * /bin/cp /var/lib/ai-gateway/db.json /backup/ai-gateway-$(date +\%F).json
  ```

- 清空业务数据前平台会**自动**生成 `data/db-backup-<时间戳>.json`，这是额外的保险。
- 「下载脱敏配置」导出的 JSON 不含密钥与密码，只适合排查/迁移结构，**不能当备份恢复**。

### 4.2 恢复

```bash
systemctl stop ai-gateway
cp /backup/ai-gateway-2026-11-03.json /var/lib/ai-gateway/db.json
systemctl start ai-gateway
```

旧版本的 `db.json` 可以直接被新版本读取：`store.load()` 会补齐缺失字段（`settings.peak`、`pricing`、`plugins`、`stats.alerts` 等），无需手工迁移。

### 4.3 升级

```bash
git pull            # 或解压新的发布包
npm test            # 可选，跑一遍 76 项端到端测试
systemctl restart ai-gateway
```

- 升级前先备份 `db.json`。
- 参考价表版本（`settings.presetsVersion`）变化时，启动会自动把新参考价补进**未定价**模型，不会覆盖你改过的价。
- 升级后建议过一遍：概览数字正常、渠道连通测试通过、发一条真实请求看日志有成本。

## 5. 排障速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 网关返回 503 | 无可用渠道且关了模拟响应 | 启用渠道，或打开「返回内置模拟响应」 |
| 网关返回 502 | 所有支持该模型的渠道都失败 | 看日志 `error`；渠道「连通测试」定位 |
| 全部 401 `invalid_key` | Key 被重置 / 员工被删 | 重新分发，或确认客户端带的是 `Bearer sk-ai-...` |
| 流式卡住不动 | Nginx 缓冲未关 | `proxy_buffering off;` |
| 请求体 413 | 超过 `settings.maxBodyBytes`（默认 4MB，无界面入口） | 停服后改 `data/db.json` 里的 `settings.maxBodyBytes` 再启动；同时反代放开 `client_max_body_size` |
| 管理台登录后立刻掉线 | 令牌 12 小时过期 | 重新登录；批量脚本需处理 401 重新取令牌 |
| 统计数字与日志对不上 | 明细只留 5000 条，聚合留 120 天 | 长期报表用聚合，短期核对用明细 |
| 服务重启后数据回退 | 旧进程未退干净，退出时用内存旧数据覆盖文件 | `pkill -f "node server.js"` 后再启动；避免同时跑两个实例 |
| CPU/内存持续涨 | 计数器在内存、单实例设计 | 单实例部署；确需横向扩展要把计数器换 Redis |

> **单实例限制**：用量计数（日/月/RPM/并发）都在进程内存，只能单实例运行。多实例共享一个 `db.json` 会互相覆盖。

## 6. 安全加固清单

- [ ] 改掉默认管理员密码（`admin/admin123`）
- [ ] `data/` 目录权限 `700`，属主为运行用户
- [ ] 管理台只在内网/VPN 可达（Nginx `allow/deny` 或安全组）
- [ ] 对外只暴露 `/v1/`（如需要）
- [ ] 定期轮换上游真实 Key（渠道编辑里填新 Key，员工无感知）
- [ ] 告警 Webhook 视为凭证：泄露后删机器人重建
- [ ] 备份文件同样含密钥，存储位置加权限
