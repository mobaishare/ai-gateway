## 1. 用量告警

额度快用完时，平台主动推送到飞书或企业微信的群机器人，不用天天盯着管理台。

告警配置是**三级结构**：员工 → 部门 → 全局。可以只配一个全局机器人（最省事），也可以给每个部门建独立的群、甚至给个别人单独配阈值——「谁超了只通知谁」。

### 1.1 触发条件

| 告警对象 | 维度 | 阈值 | 前提 |
| --- | --- | --- | --- |
| 员工 | 日 Token / 月 Token | 默认 80% / 100%，可按对象自定义 | 该员工**生效额度 > 0**（0 = 不限，不告警） |
| 部门池 | 日 Token / 月 Token | 同上 | 部门额度 > 0，**且**该员工「占用部门池」为开 |

- 只在**记账完成后**检查（`lib/alerts.js` 的 `check()` 由网关在记账后调用），不额外轮询。
- 百分比按 `used / limit` 计算并保留一位小数，超过 100% 时按 100% 显示（不会出现 130%）。
- 命中多个阈值时**逐条发**（例如同时配了 80 和 95，超 96% 时两条都会发，各自每天一次）。
- 不覆盖的维度：RPM、并发、模型权限越权。这些只能从概览页预警条和调用日志里发现。

### 1.2 通道与阈值的三级继承

每一级可以只配一部分，缺的部分自动向上一级要：

```
员工自己的告警配置  →  所属部门的告警配置  →  系统设置里的全局默认
```

- 通道（Webhook）、阈值、监控维度**各自独立回退**：员工只配了 Webhook 没配阈值，那么通道用自己的、阈值用部门的（部门也没有就用全局的）。
- 某一级「没配」的判定：开关关闭，或 Webhook 不是合法的 `http(s)://` 地址，或阈值/维度是空数组。
- 员工告警只回退到**自己所属部门**；部门告警只回退到全局。
- 全局阈值默认 `80, 100`；全局维度默认「日 Token + 月 Token」。

| 想达到的效果 | 怎么配 |
| --- | --- |
| 全公司一个群，统一 80/100 提醒 | 只配系统设置的全局机器人，部门与员工都不配 |
| 每个部门各自的群 | 每个部门配自己的 Webhook；员工的不用配 |
| 某个主管只要 95% 才提醒，且进管理群 | 该员工配 Webhook + 阈值 `95` |
| 外包团队单独一个群、只监控月额度 | 建一个部门（或用员工级）配 Webhook + 只勾「月 Token」 |
| 某员工临时静音 | 关闭该员工的告警开关（回落到部门），或把该员工移到没配告警的部门 |

### 1.3 防打扰策略

1. **每个对象 × 每个维度 × 每个阈值 × 每个统计周期只发一次**。去重键为
   `emp:<员工id>:<维度>:<阈值>:<周期>` / `dept:<部门id>:<维度>:<阈值>:<周期>`，存在 `db.stats.alerts.sent`。
2. 周期按维度取：日维度用 `YYYY-MM-DD`，月维度用 `YYYY-MM`。跨天时只清理**日维度**的键，月维度的记录保留到月底，不会被误清后重发。
3. 标记**先落盘再发送**（防抖写盘），重启不会重复发；发送失败也不会自动重试（避免刷群）。
4. 发送是异步 fire-and-forget，失败**只打服务端日志**，不阻塞也不影响员工请求。
5. 单次发送超时 8 秒（`AbortController`）。

### 1.4 消息格式

飞书自定义机器人：

```json
{ "msg_type": "text", "content": { "text": "【AI API 分流平台】个人额度预警\n李娜（研发部）日 Token 已达 82.3%：4,115,000 / 5,000,000\n通道：部门通道" } }
```

企业微信群机器人：

```json
{ "msgtype": "text", "text": { "content": "（同上文本）" } }
```

- 员工维度标题是「个人额度预警」，部门维度是「部门池预警」。
- 最后一行「通道」标明这条是**员工专属通道 / 部门通道 / 全局通道**发出来的，方便排查「为什么发到这个群」。
- 格式按 URL 自动识别：

| URL 特征 | 判定 |
| --- | --- |
| `open.feishu.cn` 或 `*.larksuite.com` | 飞书 |
| `qyapi.weixin.qq.com` | 企业微信 |
| 其他 | 默认按飞书格式发（HTTP 200 即算成功） |

### 1.5 配置步骤

**A. 全局（必做的兜底）**

1. 在群里加机器人：飞书「群设置 → 群机器人 → 添加 → 自定义机器人」；企微「群设置 → 群机器人 → 添加」，复制 Webhook。
2. 管理台 → **系统设置 → 用量告警（全局默认）** → 粘贴 Webhook → 保持「启用用量告警」开启 → 设默认阈值与维度 → **保存设置**。
3. 点 **「发送测试消息」**（用当前输入框地址发，不要求先保存）。
4. 没收到时看返回的 `message`：`HTTP 4xx` 多为地址错误、`code=19021` 多为签名校验失败、`超时` 多为出口网络不通。

**B. 部门独立通道**

部门编辑弹窗 → 「用量告警（部门级）」→ 打开「这个部门用自己的告警通道」→ 填 Webhook →（可选）阈值、维度 → 保存。列表里该部门会显示「独立告警」徽标。

**C. 员工独立通道**

员工编辑弹窗 → 「用量告警（个人级）」→ 打开开关 → 填 Webhook / 阈值 / 维度 → 保存。留空即继承部门。

**D. 测试单个对象**

部门或员工编辑弹窗里的「发送测试消息」用**解析后的真实通道**发，消息内容包含：对象、实际通道（员工专属/部门/全局）、监控维度、触发阈值、当前用量。收不到就说明这条链路没通。

也可以直接调接口：

```bash
# 全局通道测试
curl -s -X POST localhost:8787/api/settings/test-webhook \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"webhookUrl":"https://open.feishu.cn/open-apis/bot/v2/hook/xxx"}'
# → {"ok":true,"message":"已发送","type":"feishu"}

# 某个部门 / 某个员工的真实通道测试
curl -s -X POST localhost:8787/api/departments/dept_xxx/test-alert -H "Authorization: Bearer $TOKEN"
curl -s -X POST localhost:8787/api/employees/emp_xxx/test-alert  -H "Authorization: Bearer $TOKEN"
```

**E. 看发送记录**

系统设置页「最近告警」表格（接口 `GET /api/alerts`）列出最近 200 条：时间、对象、触发条件、用量、通道、结果。失败会带原因片段，测试消息标「测试」。在系统设置里点「发送测试消息」也会记一条（对象显示「全局 · 全局默认」），所以「测完没收到」能直接在表里看到失败原因。

```json
{
  "items": [
    { "id": "al_xxx", "ts": "2026-11-03T07:12:00.000Z", "target": "employee",
      "targetName": "李娜", "deptName": "研发部", "dimension": "dailyTokens",
      "threshold": 80, "percent": 82.3, "used": 4115000, "limit": 5000000,
      "channel": "department", "ok": true, "message": "已发送" }
  ],
  "total": 12, "okCount": 11, "failCount": 1,
  "routes": { "departments": [{ "id": "dept_xxx", "name": "研发部", "url": "https://open.feishu.cn/…" }], "employees": [] }
}
```

`routes` 只回域名（`https://open.feishu.cn/…`），不暴露 Webhook 全文，用于在设置页显示「哪些对象有自己的通道」。

### 1.6 告警排障

| 现象 | 排查 |
| --- | --- |
| 测试消息能收到，但用量超了没告警 | ① 系统设置里「启用用量告警」是否关着；② 该对象该维度该阈值**本周期已发过**（`db.stats.alerts.sent` 有键）；③ 额度为 0（不限）；④ 监控维度没勾月 Token 却只有月额度超了；⑤ 员工没占部门池（关掉了「占用部门池」），部门池告警不会为他触发 |
| 告警发到了错的群 | 看消息最后一行「通道」；员工配了 Webhook 就只发自己的，不会同时发部门群 |
| 「最近告警」里全是失败 | 点开看 `message`：HTTP 4xx=地址失效、`code=19021`=签名、`超时`=出口网络 |
| 服务端日志出现 `[alerts] 告警发送失败` | 同上，日志里带状态码与响应体片段 |
| 重启后又收到同一条 | 说明上次 `save()` 未落盘就崩溃；正常路径先落盘再发送 |
| 想换群 | 改对应层级的 Webhook 保存即可；去重状态不重置（本周期不会再补发旧阈值） |
| 想重发一次某阈值 | 删掉 `db.json` 里 `stats.alerts.sent` 对应的键（需停服），或用「发送测试消息」验证通道 |

## 2. 日常自检

| 检查项 | 方式 | 正常表现 |
| --- | --- | --- |
| 进程存活 | `curl -s localhost:8787/healthz` | `{"ok":true,...}`；`version` 与 `package.json` 一致 |
| 进程是不是新代码 | 侧栏底部「前端 v…」对比 `/healthz` 的 `version` | 两个版本号一致；不一致说明改了文件没重启 |
| 渠道可用 | 渠道页「连通测试」 | `ok: true`，返回耗时 |
| 计费生效 | 概览「今日模型成本」 | 有值的模型即为已定价；`—` 表示未定价 |
| 峰谷状态 | 单价卡右上角徽标 | 与当前北京时间对得上 |
| 数据落盘 | `ls -l data/db.json` | 修改时间随请求增长（有防抖，最多延迟 1 秒左右） |
| 日志积压 | 调用日志页 | 最近记录时间接近当前 |
| 日志正文在存 | 调用日志 → 任一条「详情」 | 能看到输入消息与输出正文；「内容留存已关闭」说明 `logContent=off` |
| 告警通道 | 系统设置 → 最近告警 | 有「已发送」记录；全失败说明 Webhook 失效 |

服务端日志输出到 stdout，systemd 用 `journalctl -u ai-gateway -f`，Docker 用 `docker logs -f ai-gateway`。

## 3. 部署

### 3.1 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；只给本机反代用可设 `127.0.0.1` |
| `GW_DATA_DIR` | `./data` | 数据目录（`db.json` 与备份都在这）；测试与多实例隔离都靠它 |

```bash
PORT=9000 GW_DATA_DIR=/var/lib/ai-gateway node server.js
```

### 3.2 Docker

```bash
docker build -t ai-gateway .
docker run -d --name ai-gateway \
  -p 8787:8787 \
  -v ai-gateway-data:/app/data \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  ai-gateway
```

- 镜像基于 `node:20-alpine`，内置 `HEALTHCHECK`（打 `/healthz`），`VOLUME /app/data`。
- 数据全在 `ai-gateway-data` 卷里，升级镜像 `docker pull`/重建容器不丢数据。
- 建议设 `TZ=Asia/Shanghai`：**日/月统计边界按服务器本地时区切分**，峰谷判定固定用北京时间、不受此项影响。

### 3.3 systemd

```ini
# /etc/systemd/system/ai-gateway.service
[Unit]
Description=AI API Gateway
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/ai-gateway
ExecStart=/usr/bin/node server.js
Environment=PORT=8787
Environment=GW_DATA_DIR=/var/lib/ai-gateway
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now ai-gateway
journalctl -u ai-gateway -f
```

### 3.4 Nginx 反代（流式必看）

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection '';
    proxy_buffering off;          # 必须关，否则 SSE 流式会被缓冲住
    proxy_cache off;
    proxy_read_timeout 300s;
}
```

- 反代层也要放开请求体大小（默认 1M 可能不够长上下文）：`client_max_body_size 8m;`。
- 想限制管理台来源、只对外开放 `/v1/` 时，用两个 `location` 分别控制 `allow/deny`。

### 3.5 CI

`.github/workflows/ci.yml`：推送到 `main` 或开 PR 时触发，做三件事——

1. `node --check` 检查所有 JS 语法（含 `scripts/`）；
2. `node scripts/check-docs.js` 校验文档版本号与链接（见 [docs/README §2](README.md#2-一条硬规则改代码必须同步文档)）；
3. `node test/run.js` 跑端到端测试（临时数据目录 + 独立端口，不碰真实数据）。

徽章在 README 顶部，红了自己点进去看日志。

## 4. 备份、恢复与升级

### 4.1 备份

- **全部数据就是一个文件**：`data/db.json`。停不停服都行，但建议 `cp` 前先 `curl /healthz` 确认在跑（写盘是原子 rename，直接复制不会拿到半个文件）。
- 定时备份示例（crontab，每天 2:00）：

  ```cron
  0 2 * * * /bin/cp /var/lib/ai-gateway/db.json /backup/ai-gateway-$(date +\%F).json
  ```

- 清空业务数据前平台会**自动**生成 `data/db-backup-<时间戳>.json`，这是额外的保险。
- 「下载脱敏配置」导出的 JSON 不含密钥与密码，只适合排查/迁移结构，**不能当备份恢复**。

### 4.2 恢复

```bash
systemctl stop ai-gateway
cp /backup/ai-gateway-2026-11-03.json /var/lib/ai-gateway/db.json
systemctl start ai-gateway
```

旧版本的 `db.json` 可以直接被新版本读取：`store.load()` 会补齐缺失字段（`settings.peak`、`pricing`、`plugins`、`stats.alerts`、`stats.alertLog`、`settings.alertThresholds` / `alertDimensions`、`settings.logContent` / `logContentMax` 等），无需手工迁移。旧库里部门/员工没有 `alert` 字段时按「未单独配置」处理，全部回落到全局机器人，行为与升级前一致。

v1.6 还会做一次性计价迁移（`settings.periodsMigrated` 标记，只跑一次）：把全局高峰规则 `settings.peak.enabled` 置为 `false`，并把每个只填了 `idle` 的模型翻译成等价的模型时段表。迁移前后同一时刻成本一致；升级后如果发现某模型「不分时了」，去单价弹窗看它的「自定义时段价」是否为空——为空且需要分时，就重新配时段或「载入官方参考价」。

### 4.3 升级

```bash
git pull            # 或解压新的发布包
npm test            # 可选，跑一遍 133 项端到端测试
systemctl restart ai-gateway
```

- 升级前先备份 `db.json`。
- 参考价表版本（`settings.presetsVersion`）变化时，启动会自动把新参考价补进**未定价**模型，不会覆盖你改过的价。
- 升级后建议过一遍：概览数字正常、渠道连通测试通过、发一条真实请求看日志有成本。
- **改完代码必须重启进程**：静态文件是每次请求从磁盘读的，不重启会出现「新界面 + 旧接口」（典型症状：点日志「详情」提示「接口不存在」）。核对方式：`curl -s localhost:8787/healthz`，`version` 应等于 `package.json` 的版本、`startedAt` 应是本次启动时间；不一致就说明进程还是旧的。
- 管理台也能看出：前端启动时拿 `/healthz` 的 `version` 与自身版本比对，不一致会在页面底部弹出「服务端还在运行旧代码」提示条（侧栏底部同时显示「前端 v…」）。

## 5. 排障速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 网关返回 503 | 无可用渠道且关了模拟响应 | 启用渠道，或打开「返回内置模拟响应」 |
| 网关返回 502 | 所有支持该模型的渠道都失败 | 看日志 `error`；渠道「连通测试」定位 |
| 全部 401 `invalid_key` | Key 被重置 / 员工被删 | 重新分发，或确认客户端带的是 `Bearer sk-ai-...` |
| 流式卡住不动 | Nginx 缓冲未关 | `proxy_buffering off;` |
| 请求体 413 | 超过 `settings.maxBodyBytes`（默认 4MB，无界面入口） | 停服后改 `data/db.json` 里的 `settings.maxBodyBytes` 再启动；同时反代放开 `client_max_body_size` |
| 管理台登录后立刻掉线 | 令牌 12 小时过期 | 重新登录；批量脚本需处理 401 重新取令牌 |
| 统计数字与日志对不上 | 明细只留 5000 条，聚合留 120 天 | 长期报表用聚合，短期核对用明细 |
| 日志详情里没有输入输出 | `settings.logContent = off`，或记录产生在关闭之前 | 系统设置改「摘要」，只对新记录生效 |
| 点日志「详情」提示**「接口不存在」** | 进程还在跑更新前的代码，没有 `GET /api/logs/:id` 这条路由（静态页已是最新） | `pkill -f "node server.js"` 后重启；用 `/healthz` 的 `version` 与侧栏「前端 v…」核对 |
| `db.json` 体积暴涨 | 开了「完整」留存策略，单条最多 20000 字符 × 5000 条 | 改「摘要」并把最大长度调小；或定时清理明细 |
| 服务重启后数据回退 | 旧进程未退干净，退出时用内存旧数据覆盖文件 | `pkill -f "node server.js"` 后再启动；避免同时跑两个实例 |
| CPU/内存持续涨 | 计数器在内存、单实例设计 | 单实例部署；确需横向扩展要把计数器换 Redis |

> **单实例限制**：用量计数（日/月/RPM/并发）都在进程内存，只能单实例运行。多实例共享一个 `db.json` 会互相覆盖。

## 6. 安全加固清单

- [ ] 改掉默认管理员密码（`admin/admin123`）
- [ ] `data/` 目录权限 `700`，属主为运行用户
- [ ] 管理台只在内网/VPN 可达（Nginx `allow/deny` 或安全组）
- [ ] 对外只暴露 `/v1/`（如需要）
- [ ] 定期轮换上游真实 Key（渠道编辑里填新 Key，员工无感知）
- [ ] 告警 Webhook 视为凭证：泄露后删机器人重建
- [ ] 调用日志正文（`settings.logContent`）按合规要求设定：涉及个人信息/业务机密的环境建议 `summary` 或 `off`，密钥虽自动打码但业务内容不会
- [ ] 备份文件同样含密钥，存储位置加权限
