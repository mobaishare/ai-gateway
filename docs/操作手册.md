# AI API 分流平台 · 操作手册

> 适用版本：**v1.3.4**（版本历史见 [CHANGELOG.md](../CHANGELOG.md)）
>
> 读者：平台管理员（IT / 内部工具负责人）。部署与排障见 [告警与运维手册](告警与运维手册.md)，计价细节见 [计费与成本核算](计费与成本核算.md)。

---

## 1. 平台是做什么的

一句话：**员工不用管真实 AI 密钥，平台统一分配虚拟 Key、按部门/员工控制用量与可用模型，请求按权重分流到各个上游，并按模型单价核算成本。**

```
员工代码 ──Bearer sk-ai-xxx──▶ 分流平台
                                ├─ 1. 校验虚拟 Key（不是真实密钥）
                                ├─ 2. 模型权限：员工特例 优先于 部门白名单
                                ├─ 3. 检查配额：员工特例 优先于 部门默认
                                ├─ 4. 按权重选中上游渠道，失败自动切换
                                └─ 5. 记账：Token 用量 + 成本落到员工/部门/日志 → 触发用量告警
真实 Key 只存在服务端，员工永远接触不到。
```

技术形态：Node.js 单进程 + 单文件 `data/db.json`，零外部依赖，`node server.js` 即可运行。

## 2. 快速开始

```bash
cd ai-gateway
node server.js          # 或 npm start；开发时 npm run dev 可自动重启
```

- 管理台：`http://localhost:8787/`
- 网关地址：`http://localhost:8787/v1`
- 健康检查：`http://localhost:8787/healthz`
- 默认管理员：`admin / admin123` —— **登录后第一件事去「系统设置」改密码。**

首次启动会生成演示数据（4 个部门、7 名员工、3 个示例渠道、8 家厂商 37 个模型的参考单价）。所有渠道默认停用，此时网关返回**内置模拟响应**，不配真实 Key 也能把配额与计费流程跑通。

Docker 与 systemd 部署见 [告警与运维手册 · 部署](告警与运维手册.md#3-部署)。

## 3. 各页面操作说明

左侧导航共 8 页：概览、部门管理、员工管理、上游渠道、调用日志、接入文档、扩展插件、系统设置。

### 3.1 概览

| 区域 | 内容 |
| --- | --- |
| 今日 Token | 今日 token 合计、请求次数、**今日成本**（¥）；当天处于空闲计价时段且存在分时定价模型时，显示 `🌙 空闲时段计价中` |
| 本月 Token | 本月累计 token、请求次数、**本月成本** |
| 员工与特例 | 启用员工数 / 总人数，以及其中设置过特例额度的人数 |
| 上游渠道 | 启用渠道数 / 总数；全部停用时提示「当前走内置模拟响应」 |
| 额度预警 | 任一员工或部门日额度 ≥ 80% 黄条、≥ 100% 红条 |
| 近 7 日用量趋势 | 全平台 token 消耗柱状图 |
| 部门用量 | 按今日消耗排序，带进度条与部门今日成本 |
| 员工用量 Top 10 | 今日 token、今日成本、生效额度与进度 |
| 今日模型成本 | 按模型汇总请求数、token、成本与成本占比，右上角「配置单价」直达渠道页 |

> 成本为 0 通常是因为该模型没配单价，或用量记录发生在配置单价之前。历史记录不会被重算（见 [计费手册](计费与成本核算.md#6-常见核对问题)）。

### 3.2 部门管理

部门是额度的第一层来源。新建/编辑时可设置：

| 字段 | 说明 |
| --- | --- |
| 部门名称 / 备注 | 名称必填，参与插件同步时的合并（按名称匹配） |
| 每日 / 每月 Token | 留空或 `0` 表示该维度不限制 |
| RPM / 并发 | 每分钟请求数、同时进行的请求数；留空或 `0` 不限 |
| **模型白名单** | 可选，逗号分隔，支持通配（如 `gpt-4o-mini, deepseek*`）。填了之后该部门只能调用列表内模型，越权返回 403 |
| 渠道绑定 | 可选，勾选后该部门流量**只在选中渠道里分流**，实现「研发走内网代理、市场走官方 API」的隔离 |
| 启用该部门 | 停用后该部门所有人无法调用（403 `dept_disabled`） |

> 删除部门前必须先转移或删除部门下的员工，平台会拒绝直接删除。

### 3.3 员工管理（核心）

表格里每位员工一行：姓名/邮箱、部门、**API KEY（打码 + 一键复制）**、额度来源、今日用量、本月 Token、状态，以及「配额详情 / 编辑」。

#### 3.3.1 额度规则（重点）

员工默认继承所属部门的配额；开了「特例」后按维度逐个判断：

| 特例里怎么填 | 该维度生效值 |
| --- | --- |
| 填数字 | 压过部门（可以更大也可以更小） |
| 留空 | 继续继承部门 |
| 填 `0` | 该维度不限制 |

四个维度（日/月 Token、RPM、并发）各自独立判断。编辑弹窗下方有「当前生效额度」实时预览表，边填边能看到每一条最终生效的是谁、来源是员工还是部门。

特例还支持两个开关：

- **过期时间**：到期自动回落到部门额度，适合临时提额（如大促值班）。
- **占用部门池**：默认开。给算法组/外包单独核算时关掉，他的用量不消耗部门预算（列表里会标「特例 · 独立额度」）。

#### 3.3.2 模型权限（与额度同一套继承规则）

员工特例里可填「**允许的模型**」（留空 = 继承部门策略）：

| 填写情况 | 生效白名单 |
| --- | --- |
| 员工特例里填了模型 | **整体覆盖**部门白名单（不是取交集） |
| 员工特例留空 | 继承部门白名单 |
| 员工和部门都没填 | 不限制，可调用任何模型 |

- 支持通配：`gpt-4o*` 匹配所有以此开头的模型；`*` 等价于不限制。
- 特例过期后，模型白名单与额度一起回落到部门策略。
- 越权调用返回 **403 `model_not_allowed`**，并在调用日志里留一条「失败」记录，写明允许列表与限制来源（个人 / 部门）。

#### 3.3.3 密钥操作

- 复制：员工列表行内「复制」，或详情弹窗里显示/复制完整值。
- 重置：详情弹窗「重置密钥」，旧 Key 立即失效（员工离职 / Key 泄露时用）。
- 重置用量：只清该员工自己的日/月聚合，**不动部门池统计**（部门池是多人累加值，无法精确回退一个人的贡献）。

### 3.4 上游渠道

| 字段 | 说明 |
| --- | --- |
| Base URL | 只填域名，如 `https://api.openai.com`，平台自动拼 `/v1/chat/completions` |
| API Key | 真实密钥，**任何接口返回时都打码**，重新编辑时留空即不覆盖 |
| 支持的模型 | 逗号分隔；留空=全部；支持前缀通配，如 `gpt-4o*` |
| 权重 | 同一模型有多个渠道时按权重加权随机分流 |
| 超时 | 单次上游请求超时（毫秒，最低 1000） |

- **连通测试**：保存后点一下，验证地址和 Key 是否可用。
- **故障切换**：某渠道 5xx/超时，自动切到下一个支持该模型的渠道；全部失败返回 502。
- 渠道全部停用时：若设置里开了「没有可用渠道时返回内置模拟响应」，请求会拿到模拟回答（便于先跑通流程），否则返回 503。

#### 3.4.1 模型单价与成本核算

页面下方「模型单价」卡片维护每个模型的价格（**元 / 百万 tokens**），与转发本身无关，只影响记账时的成本折算。

**卡片头部**：显示当前时段徽标（`当前：高峰时段` / `当前：空闲时段`）、「载入官方参考价」、「保存单价」两个按钮。

**高峰时段规则栏**（单价表上方，北京时间 UTC+8）：

- 规则贴合 DeepSeek 官方：**周一至周五（不含法定节假日）9:00–12:00、14:00–18:00 为高峰，其余（含周末、法定节假日全天）为空闲**。
- 可调整：高峰星期（复选）、最多两个高峰时间窗、法定节假日列表（`YYYY-MM-DD`，逗号分隔，当天全天按空闲价）。
- 关闭开关后不再区分时段，全部按输入/输出价计。

**单价表 9 列**（双行分组表头：左侧「峰时（默认）」四列 + 右侧「空闲时段」四列，中间有竖线分隔）：

| 列 | 说明 |
| --- | --- |
| 模型 | 来自所有渠道声明的模型 + 单价表已有模型 + 最后一行可新增 |
| 峰时 · 输入 / 输出 | 高峰（默认）单价，必填才算「已定价」 |
| 峰时 · 缓存命中 | 可选。上游返回的缓存命中 tokens 按此价计（DeepSeek `prompt_cache_hit_tokens`、OpenAI `cached_tokens`、Kimi 缓存命中）；留空按峰时输入价 |
| 峰时 · 缓存写入 | 可选。Anthropic `cache_creation_input_tokens`、Kimi 缓存写入按此价计；留空按峰时输入价 |
| 空闲 · 输入 / 输出 | 可选。留空=该模型不分时；填写后空闲时段按此价 |
| 空闲 · 缓存命中 | 可选。**空闲时段**的缓存命中价（如 DeepSeek 空闲缓存命中远低于峰时）。留空按空闲输入价，再留空则按峰时输入价 |
| 空闲 · 缓存写入 | 可选。**空闲时段**的缓存写入价（如 Anthropic / Kimi 在空闲时段有单独定价）。留空规则同上 |

> DeepSeek 就是典型：`deepseek-flash` 峰时输入 ¥2 / 输出 ¥8 / 缓存命中 ¥0.04，空闲时输入 ¥1 / 输出 ¥4 / 缓存命中 ¥0.02。四个空闲字段都要填，空闲时段的缓存请求才不会被按峰时缓存价（或空闲输入价）多算。

**高级定价（JSON）**：单价表下方的卡片可编辑完整定价对象，用于配置 `tiers`（按输入长度分档，如通义千问阶梯价、Gemini 200K 断点）等进阶字段。保存时以「主表」值为准合并，高级字段（`tiers`、未在表格中出现的字段）保留。

**计费口径速记**（完整说明与算例见 [计费与成本核算](计费与成本核算.md)）：

- 价格随官方调整，以各厂商账单为准；内置参考价核对日期见计费手册。
- 成本按**每次请求发生时刻**所处时段计价并随明细落盘，事后调整单价不影响历史记录。
- 未配置单价的模型成本记 0，前端显示「未定价」。

### 3.5 调用日志

每次请求一行：时间、员工（含部门）、模型、渠道、Token、**成本**、耗时、状态。状态分三类：

| 状态 | 含义 |
| --- | --- |
| 成功 | 上游正常返回 |
| 配额拦截 | 被配额检查拦下（429），`error` 字段写明是哪个维度、员工还是部门 |
| 失败 | 模型越权（403）、上游错误、鉴权失败等，`error` 写明原因 |

- 顶部下拉可按状态过滤；接口支持按员工 / 部门过滤（见 [API 参考](API参考.md#26-调用日志)）。
- 日志里同时记录 `promptTokens`、`completionTokens`、`cacheTokens`、`cacheWriteTokens`、`cost`，可直接用于对账。
- 明细保留最近 5000 条；日报/月报聚合保留 120 天。

### 3.6 接入文档

自动填充当前平台地址与所选员工的完整 Key，并给出 curl / Python / Node 三种示例，可直接复制发给同事。页面上可切换员工，避免把某个人的 Key 当通用 Key 发出去。

### 3.7 扩展插件（批量导入组织架构）

两级结构：插件列表点卡片 → 进入该插件的配置页（地址形如 `#/plugins/feishu`，可收藏）。

| 插件 | 需要填 | 凭证在哪拿 |
| --- | --- | --- |
| 飞书通讯录 | App ID、App Secret（可选 API 域名，海外 Lark 换 `https://open.larksuite.com`） | 飞书开放平台 → 开发者后台 → 企业自建应用；需开通「获取部门基础信息」「获取成员基础信息」权限 |
| 企业微信通讯录 | 企业 ID、通讯录 Secret | 企微管理后台 → 管理工具 → 通讯录同步 → 开启并查看 Secret |
| 文本 / CSV 导入 | 粘贴文本即可 | 无。每行 `姓名,邮箱,部门`，邮箱可省略，首行若为「姓名」自动当表头 |

每个插件三个按钮：**保存配置**、**连接测试**（报出能拉到几个部门/几个人）、**立即同步**。

**同步规则（幂等，可反复执行）**：

1. 部门按**名称**合并：已存在的不动，新的自动创建（额度为 0，同步完自己分配）。
2. 员工按**邮箱**匹配，其次**同名**：已有员工只更新归属部门，**不覆盖你已设置的额度、密钥与模型白名单**。
3. 新员工自动签发虚拟 Key，去「员工管理」复制发给他。
4. 飞书侧的离职成员自动跳过。

自行接入钉钉 / LDAP / HR 系统见 [插件开发手册](插件开发手册.md)。

### 3.8 系统设置

页面分五块：

1. **基础设置**：平台名称、额度用尽策略（当前推荐「直接拒绝 429」）、「没有可用渠道时返回内置模拟响应」开关。
2. **修改管理员密码**：需校验原密码，新密码至少 6 位。
3. **用量告警**：机器人 Webhook 地址 + 启用开关 + 「发送测试消息」。支持飞书自定义机器人与企业微信群机器人，按 URL 自动识别格式。详见 [告警与运维手册](告警与运维手册.md#1-用量告警)。
4. **数据管理 → 清空业务数据**：清掉部门/员工/日志/统计，**保留上游渠道与模型单价、平台设置、插件配置**；清空前自动备份到 `data/db-backup-<时间戳>.json`，清空后重启也不会再灌演示数据。
5. **数据备份 → 下载脱敏配置**：导出的 JSON 不含任何密钥与密码，适合排查问题或迁移结构。

> `data/db.json` 就是全部数据，拷走即完整备份。

## 4. 员工侧指引（可直接转发）

1. 找管理员拿两样东西：**接入地址**（如 `http://内网IP:8787/v1`）和你的**专属 Key**（`sk-ai-` 开头）。这是平台签发的虚拟 Key，不是任何上游服务的真实密钥。
2. 原有 OpenAI SDK 只改 `base_url` 和 `api_key` 两行就能用，支持流式输出。常用客户端（Dify / Cherry Studio 等）在「自定义 OpenAI 接口」里填同样两样。
3. 只能调用管理员给你的模型范围（部门或个人的白名单）。调用范围外模型会收到 **403**：

   ```json
   {
     "error": {
       "type": "model_not_allowed",
       "code": "model_not_allowed",
       "message": "没有权限使用模型「gpt-5.5」（部门策略限制，允许：gpt-4o-mini、deepseek*）"
     }
   }
   ```

4. 额度用完会收到 429，返回体里写明了是**你自己的额度**还是**部门池**用完、是哪个维度（日/月/RPM/并发），找管理员调整即可。
5. Key 泄露就找管理员重置，重置后旧 Key 立即失效。

示例：

```bash
curl http://<平台地址>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-ai-你的虚拟Key" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'
```

## 5. 常见问题

| 问题 | 处理 |
| --- | --- |
| 员工反馈 429 | 看返回体里的 `scope`（employee/department）和 `dimension`，到对应页面调额度即可 |
| 员工反馈 403 `model_not_allowed` | 到员工编辑 → 特例 → 「允许的模型」或部门 → 「模型白名单」里补上该模型（支持 `xxx*`） |
| 想临时给某人提额 | 员工编辑 → 开特例 → 填需要的值 → 设过期时间，到期自动回落 |
| 想临时给某人开某个模型 | 员工编辑 → 开特例 → 「允许的模型」填该模型（会整体覆盖部门白名单，需要把其他要用的模型一起写上） |
| 员工离职 | 直接删除员工，或先停用再删；他的 Key 立即失效，其他人不受影响 |
| 换上游密钥 | 渠道编辑里填新 Key，员工侧无感知 |
| 成本一直是 0 | 该模型没配单价；到「上游渠道 → 模型单价」填输入/输出价，只对新产生的用量生效 |
| 空闲价没生效 | 检查单价表上方高峰规则开关、时间窗、节假日；模型必须填了「空闲输入/输出」才分时；页面徽标会显示当前时段 |
| 用量告警没收到 | 先点「发送测试消息」验证 Webhook；同一对象同一阈值每天只推一次；只有「日额度」维度会触发告警 |
| 流式输出卡住 | 检查 Nginx 是否关了 `proxy_buffering` |
| 数据丢了 | 恢复最近一次 `db.json` 备份；清空操作本身也会先自动备份 |
| 想多实例部署 | 暂不支持：计数器在内存，只能单实例；横向扩展需把 `lib/store.js` 计数器换 Redis |

## 6. 安全须知

- 管理台只有一道管理员密码，务必改掉默认密码，并限制管理台的访问来源（内网 / VPN）。
- 虚拟 Key 在服务端明文存储（为了管理员能随时复制分发）。若安全要求更高，可改为只存哈希——代价是平台自己也看不到完整 Key，只能「重置后重新分发」。
- 插件凭证（飞书 Secret、企微 Secret）、上游真实 Key、告警 Webhook 全部随 `db.json` 存储，注意该文件目录权限（建议 `700`）。
- 「下载脱敏配置」导出的是脱敏结果，不要把 `data/db.json` 原文发给外部。
