# AI API 分流平台 · 操作手册

> 适用版本：v1.1.0（版本历史见 [CHANGELOG.md](../CHANGELOG.md)）
>
> 读者：平台管理员（IT / 内部工具负责人）。

---

## 1. 平台是做什么的

一句话：**员工不用管真实 AI 密钥，平台统一分配虚拟 Key、按部门/员工控制用量，请求按权重分流到各个上游。**

```
员工代码 ──Bearer sk-ai-xxx──▶ 分流平台
                                ├─ 1. 校验虚拟 Key（不是真实密钥）
                                ├─ 2. 检查配额：员工特例 优先于 部门默认
                                ├─ 3. 按权重选中上游渠道，失败自动切换
                                └─ 4. 记账：Token 用量落到员工/部门/日志
真实 Key 只存在服务端，员工永远接触不到。
```

技术形态：Node.js 单进程 + 单文件 `data/db.json`，零外部依赖，`node server.js` 即可运行。

---

## 2. 快速开始

```bash
cd ai-gateway
node server.js          # 或 npm start；开发时 npm run dev 可自动重启
```

- 管理台：`http://localhost:8787/`
- 网关地址：`http://localhost:8787/v1`
- 健康检查：`http://localhost:8787/healthz`
- 默认管理员：`admin / admin123` —— **登录后第一件事去「系统设置」改密码。**

## 3. 各页面操作说明

### 3.1 概览

- 今日/本月 Token 与请求次数、渠道启用情况、7 日用量趋势。
- 部门排行与员工 Top：谁用得最多一目了然。
- **超额预警**：任一员工/部门用量 ≥ 80% 出黄条，≥ 100% 出红条。

### 3.2 部门管理

部门是额度的第一层来源。新建/编辑时可设置：

| 字段 | 说明 |
| --- | --- |
| 每日/每月 Token | 填 0 或留空表示该维度不限制 |
| RPM / 并发 | 每分钟请求数、同时进行的请求数 |
| 可用渠道 | 勾选后该部门的流量**只在选中的渠道里分流**，实现「研发走内网代理、市场走官方 API」这类隔离 |
| 状态 | 停用后该部门所有人无法调用 |

> 删除部门前必须先转移或删除部门下的员工，平台会拒绝直接删除。

### 3.3 员工管理（核心）

表格里每位员工一行：姓名、部门、**API KEY（打码 + 一键复制）**、额度来源、今日用量、本月 Token、状态。

**额度规则（重点）**：员工默认继承所属部门的配额；开了「特例」后按维度逐个判断：

| 特例里怎么填 | 该维度生效值 |
| --- | --- |
| 填数字 | 压过部门（可以更大也可以更小） |
| 留空 | 继续继承部门 |
| 填 `0` | 该维度不限制 |

四个维度（日/月 Token、RPM、并发）各自独立判断。编辑弹窗下方有「当前生效额度」实时预览表，边填边能看到每一条最终生效的是谁、来源是员工还是部门。

特例还支持两个开关：

- **过期时间**：到期自动回落到部门额度，适合临时提额（如大促值班）。
- **占用部门池**：默认开。给算法组/外包单独核算时关掉，他的用量不消耗部门预算。

**密钥操作**：

- 复制：员工列表行内「复制」，或详情弹窗里显示/复制完整值。
- 重置：详情弹窗「重置密钥」，旧 Key 立即失效（员工离职/Key 泄露时用）。
- 重置用量：只清该员工自己的日/月聚合，**不动部门池统计**（部门池是多人累加值，无法精确回退一个人的贡献）。

### 3.4 上游渠道

| 字段 | 说明 |
| --- | --- |
| Base URL | 只填域名，如 `https://api.openai.com`，平台自动拼 `/v1/chat/completions` |
| API Key | 真实密钥，**任何接口返回时都打码**，重新编辑时留空即不覆盖 |
| 支持的模型 | 逗号分隔；留空=全部；支持前缀通配，如 `gpt-4o*` |
| 权重 | 同一模型有多个渠道时按权重加权随机分流 |
| 超时 | 单次上游请求超时（毫秒，最低 1000） |

- **连通测试**：保存后点一下，验证地址和 Key 是否可用。
- **故障切换**：某渠道 5xx/超时，自动切到下一个支持该模型的渠道；全部失败返回 502。
- 渠道全部停用时：若设置里开了「没有可用渠道时返回内置模拟响应」，请求会拿到模拟回答（便于先跑通流程），否则返回 503。

### 3.5 调用日志

每次请求一行：时间、员工、部门、模型、渠道、Token 明细、耗时、状态。支持按状态（成功/拒绝/错误）、员工、部门过滤。**被配额拒绝的请求也会记录**，并写明拒绝原因。

### 3.6 扩展插件（批量导入组织架构）

两级结构：插件列表点卡片 → 进入该插件的配置页。

| 插件 | 需要填 | 凭证在哪拿 |
| --- | --- | --- |
| 飞书通讯录 | App ID、App Secret（可选 API 域名，海外 Lark 换 `https://open.larksuite.com`） | 飞书开放平台 → 开发者后台 → 企业自建应用；需开通「获取部门基础信息」「获取成员基础信息」权限 |
| 企业微信通讯录 | 企业 ID、通讯录 Secret | 企微管理后台 → 管理工具 → 通讯录同步 → 开启并查看 Secret |
| 文本 / CSV 导入 | 粘贴文本即可 | 无。每行 `姓名,邮箱,部门`，邮箱可省略，首行若为「姓名」自动当表头 |

每个插件三个按钮：**保存配置**、**连接测试**（报出能拉到几个部门/几个人）、**立即同步**。

**同步规则（幂等，可反复执行）**：

1. 部门按**名称**合并：已存在的不动，新的自动创建（额度为 0，同步完自己分配）。
2. 员工按**邮箱**匹配，其次**同名**：已有员工只更新归属部门，**不覆盖你已设置的额度和密钥**。
3. 新员工自动签发虚拟 Key，去「员工管理」复制发给他。
4. 飞书侧的离职成员自动跳过。

### 3.7 系统设置

- 平台名称、额度用尽策略（当前推荐「直接拒绝 429」）、模拟响应开关。
- **数据管理 → 清空业务数据**：清掉部门/员工/日志/统计，**保留渠道与模型、平台设置、插件配置**；清空前自动备份到 `data/db-backup-<时间戳>.json`，清空后重启也不会再灌演示数据。
- 数据备份：`data/db.json` 就是全部数据，拷走即备份；「下载脱敏配置」导出的 JSON 不含任何密钥与密码。
- 修改管理员密码。

## 4. 员工侧指引（可直接转发）

1. 找管理员拿两样东西：**接入地址**（如 `http://内网IP:8787/v1`）和你的**专属 Key**（`sk-ai-` 开头）。这是平台签发的虚拟 Key，不是任何上游服务的真实密钥。
2. 原有 OpenAI SDK 只改 `base_url` 和 `api_key` 两行就能用，支持流式输出。常用客户端（Dify / Cherry Studio 等）在「自定义 OpenAI 接口」里填同样两样。
3. 额度用完会收到 429，返回体里写明了是**你自己的额度**还是**部门池**用完、是哪个维度（日/月/RPM/并发），找管理员调整即可。
4. Key 泄露就找管理员重置，重置后旧 Key 立即失效。

示例：

```bash
curl http://<平台地址>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-ai-你的虚拟Key" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'
```

## 5. 部署到内网服务器

### systemd 常驻

```ini
# /etc/systemd/system/ai-gateway.service
[Unit]
Description=AI API Gateway
After=network.target

[Service]
WorkingDirectory=/opt/ai-gateway
ExecStart=/usr/bin/node server.js
Environment=PORT=8787
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now ai-gateway
```

### Nginx 反代（注意流式）

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;          # 必须关，否则流式输出会卡住
    proxy_cache off;
    proxy_read_timeout 300s;
}
```

环境变量：`PORT`（默认 8787）、`HOST`（默认 0.0.0.0）、`GW_DATA_DIR`（数据目录，默认 `./data`）。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| 员工反馈 429 | 看返回体里的 `scope`（employee/department）和 `dimension`，到对应页面调额度即可 |
| 想临时给某人提额 | 员工编辑 → 开特例 → 填需要的值 → 设过期时间，到期自动回落 |
| 员工离职 | 直接删除员工，或先停用再删；他的 Key 立即失效，其他人不受影响 |
| 换上游密钥 | 渠道编辑里填新 Key，员工侧无感知 |
| 流式输出卡住 | 检查 Nginx 是否关了 `proxy_buffering` |
| 数据丢了 | 恢复最近一次 `db.json` 备份；清空操作本身也会先自动备份 |
| 想多实例部署 | 暂不支持：计数器在内存，只能单实例；横向扩展需把 `lib/store.js` 计数器换 Redis |

## 7. 安全须知

- 管理台只有一道管理员密码，务必改掉默认密码，并限制管理台的访问来源（内网/VPN）。
- 虚拟 Key 在服务端明文存储（为了管理员能随时复制分发）。若安全要求更高，可改为只存哈希——代价是平台自己也看不到完整 Key，只能「重置后重新分发」。
- 插件凭证（飞书 Secret、企微 Secret）随 `db.json` 存储，注意该文件的目录权限（建议 `700`）。
