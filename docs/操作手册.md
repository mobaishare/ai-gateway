# AI API 分流平台 · 操作手册

> 适用版本：**v1.6.4**（版本历史见 [CHANGELOG.md](../CHANGELOG.md)）
>
> 读者：平台管理员（IT / 内部工具负责人）。部署与排障见 [告警与运维手册](告警与运维手册.md)，计价细节见 [计费与成本核算](计费与成本核算.md)。

---

## 1. 平台是做什么的

一句话：**员工不用管真实 AI 密钥，平台统一分配虚拟 Key、按部门/员工控制用量与可用模型，请求按权重分流到各个上游，并按模型单价核算成本。**

```
员工代码 ──Bearer sk-ai-xxx──▶ 分流平台
                                ├─ 1. 校验虚拟 Key（不是真实密钥）
                                ├─ 2. 模型权限：员工特例 优先于 部门白名单
                                ├─ 3. 检查配额：员工特例 优先于 部门默认
                                ├─ 4. 按权重选中上游渠道，失败自动切换
                                └─ 5. 记账：Token 用量 + 成本落到员工/部门/日志 → 触发用量告警
真实 Key 只存在服务端，员工永远接触不到。
```

技术形态：Node.js 单进程 + 单文件 `data/db.json`，零外部依赖，`node server.js` 即可运行。

## 2. 快速开始

```bash
cd ai-gateway
node server.js          # 或 npm start；开发时 npm run dev 可自动重启
```

- 管理台：`http://localhost:8787/`
- 网关地址：`http://localhost:8787/v1`
- 健康检查：`http://localhost:8787/healthz`（返回 `version` 与 `startedAt`，可用来确认进程是不是最新代码）
- 默认管理员：`admin / admin123` —— **登录后第一件事去「系统设置」改密码。**

首次启动会生成演示数据（4 个部门、7 名员工、3 个示例渠道、8 家厂商 37 个模型的参考单价）。所有渠道默认停用，此时网关返回**内置模拟响应**，不配真实 Key 也能把配额与计费流程跑通。

Docker 与 systemd 部署见 [告警与运维手册 · 部署](告警与运维手册.md#3-部署)。

## 3. 各页面操作说明

左侧导航共 8 页：概览、部门管理、员工管理、上游渠道、调用日志、接入文档、扩展插件、系统设置。

### 3.1 概览

| 区域 | 内容 |
| --- | --- |
| 今日 Token | 今日 token 合计、请求次数、**今日成本**（¥）；当天处于空闲计价时段且存在分时定价模型时，显示 `🌙 空闲时段计价中` |
| 本月 Token | 本月累计 token、请求次数、**本月成本** |
| 员工与特例 | 启用员工数 / 总人数，以及其中设置过特例额度的人数 |
| 上游渠道 | 启用渠道数 / 总数；全部停用时提示「当前走内置模拟响应」 |
| 额度预警 | 任一员工或部门日额度 ≥ 80% 黄条、≥ 100% 红条 |
| 近 7 日用量趋势 | 全平台 token 消耗柱状图 |
| 部门用量 | 按今日消耗排序，带进度条与部门今日成本 |
| 员工用量 Top 10 | 今日 token、今日成本、生效额度与进度 |
| 今日模型成本 | 按模型汇总请求数、token、成本与成本占比，右上角「配置单价」直达渠道页 |

> 成本为 0 通常是因为该模型没配单价，或用量记录发生在配置单价之前。历史记录不会被重算（见 [计费手册](计费与成本核算.md#6-常见核对问题)）。

### 3.2 部门管理

部门是额度的第一层来源。新建/编辑时可设置：

| 字段 | 说明 |
| --- | --- |
| 部门名称 / 备注 | 名称必填，参与插件同步时的合并（按名称匹配） |
| 每日 / 每月 Token | 留空或 `0` 表示该维度不限制 |
| RPM / 并发 | 每分钟请求数、同时进行的请求数；留空或 `0` 不限 |
| **模型白名单** | 可选，逗号分隔，支持通配（如 `gpt-4o-mini, deepseek*`）。填了之后该部门只能调用列表内模型，越权返回 403 |
| 渠道绑定 | 可选，勾选后该部门流量**只在选中渠道里分流**，实现「研发走内网代理、市场走官方 API」的隔离 |
| **用量告警（部门级）** | 可选。打开后该部门的额度告警发到**本部门自己的群**（Webhook 留空则用全局机器人）；阈值与监控维度可单独设，留空=继承系统设置的全局默认。列表里会标「独立告警」 |
| 启用该部门 | 停用后该部门所有人无法调用（403 `dept_disabled`） |

> 删除部门前必须先转移或删除部门下的员工，平台会拒绝直接删除。

### 3.3 员工管理（核心）

表格里每位员工一行：姓名/邮箱、部门、**API KEY（打码 + 一键复制）**、额度来源、今日用量、本月 Token、状态，以及「配额详情 / 编辑」。

#### 3.3.1 额度规则（重点）

员工默认继承所属部门的配额；开了「特例」后按维度逐个判断：

| 特例里怎么填 | 该维度生效值 |
| --- | --- |
| 填数字 | 压过部门（可以更大也可以更小） |
| 留空 | 继续继承部门 |
| 填 `0` | 该维度不限制 |

四个维度（日/月 Token、RPM、并发）各自独立判断。编辑弹窗下方有「当前生效额度」实时预览表，边填边能看到每一条最终生效的是谁、来源是员工还是部门。

特例还支持两个开关：

- **过期时间**：到期自动回落到部门额度，适合临时提额（如大促值班）。
- **占用部门池**：默认开。给算法组/外包单独核算时关掉，他的用量不消耗部门预算（列表里会标「特例 · 独立额度」）。

#### 3.3.2 模型权限（与额度同一套继承规则）

员工特例里可填「**允许的模型**」（留空 = 继承部门策略）：

| 填写情况 | 生效白名单 |
| --- | --- |
| 员工特例里填了模型 | **整体覆盖**部门白名单（不是取交集） |
| 员工特例留空 | 继承部门白名单 |
| 员工和部门都没填 | 不限制，可调用任何模型 |

- 支持通配：`gpt-4o*` 匹配所有以此开头的模型；`*` 等价于不限制。
- 特例过期后，模型白名单与额度一起回落到部门策略。
- 越权调用返回 **403 `model_not_allowed`**，并在调用日志里留一条「失败」记录，写明允许列表与限制来源（个人 / 部门）。

#### 3.3.3 密钥操作

- 复制：员工列表行内「复制」，或详情弹窗里显示/复制完整值。
- 重置：详情弹窗「重置密钥」，旧 Key 立即失效（员工离职 / Key 泄露时用）。
- 重置用量：只清该员工自己的日/月聚合，**不动部门池统计**（部门池是多人累加值，无法精确回退一个人的贡献）。

#### 3.3.4 个人用量告警

员工编辑弹窗底部有「用量告警（个人级）」小节，用来给**个别人**单独配告警：

| 字段 | 说明 |
| --- | --- |
| 用自己的告警通道 | 开关。关闭 = 完全继承部门（再继承全局），行为与旧版一致 |
| 告警机器人 Webhook | 留空 = 用所属部门的群，部门没配再用全局机器人；填了 = 该员工的告警**只发到这个群** |
| 触发阈值（%） | 逗号分隔，如 `50, 80, 95`；留空 = 继承部门/全局（默认 80、100） |
| 监控维度 | 日 Token / 月 Token，可都选；留空 = 继承部门/全局 |

- 员工详情弹窗（表格里点姓名）也会显示当前生效的告警通道来源：员工专属通道 / 部门通道 / 全局通道。
- 需要「主管只要 95% 才提醒」「外包单独进一个群」这类诉求，就在这里配；部门整体换群只改部门，不用逐个改人。
- 保存后可在员工列表点「测试告警」发一条测试消息验证通道是否通（消息里写明对象、实际通道、维度、阈值与当前用量）。

### 3.4 上游渠道

| 字段 | 说明 |
| --- | --- |
| Base URL | 只填域名，如 `https://api.openai.com`，平台自动拼 `/v1/chat/completions` |
| API Key | 真实密钥，**任何接口返回时都打码**，重新编辑时留空即不覆盖 |
| 支持的模型 | 逗号分隔；留空=全部；支持前缀通配，如 `gpt-4o*` |
| 权重 | 同一模型有多个渠道时按权重加权随机分流 |
| 超时 | 单次上游请求超时（毫秒，最低 1000） |

- **连通测试**：保存后点一下，验证地址和 Key 是否可用。
- **故障切换**：某渠道 5xx/超时，自动切到下一个支持该模型的渠道；全部失败返回 502。
- 渠道全部停用时：若设置里开了「没有可用渠道时返回内置模拟响应」，请求会拿到模拟回答（便于先跑通流程），否则返回 503。

#### 3.4.1 模型单价与成本核算

页面下方「模型单价」卡片维护每个模型的价格（**元 / 百万 tokens**），与转发本身无关，只影响记账时的成本折算。

**卡片头部**：显示计价形态徽标——默认是 `按模型时段计价 · N 个模型已配`，打开全局规则后变回 `当前：高峰时段` / `当前：空闲时段`；右侧是「载入官方参考价」「保存单价」。

**全局高峰时段栏**（单价表上方，北京时间 UTC+8，**默认不勾选**）：

- 这是**旧版兜底方案**（`settings.peak`）：只有「模型填了右侧空闲价、又没配自定义时段」时才需要它。默认关闭，避免「给模型单独配了时段，却被全局规则盖住」。
- 勾上后规则为：周一至周五（不含法定节假日）9:00–12:00、14:00–18:00 为高峰，其余（含周末、法定节假日全天）为空闲。
- 可调整高峰星期（复选）、最多两个高峰时间窗、法定节假日列表（`YYYY-MM-DD`，当天全天按空闲价）。
- 日常分时请用下面的**自定义时段价**（按模型配），不依赖这个开关。

**单价表 10 列**（双行分组表头：左侧「基础价 / 峰时」四列 + 右侧「空闲价（全局规则）」四列，另有模型与自定义两列）：

| 列 | 说明 |
| --- | --- |
| 模型 | 来自所有渠道声明的模型 + 单价表已有模型 + 最后一行可新增 |
| 基础价 · 输入 / 输出 | 该模型的基准单价，必填才算「已定价」；配了自定义时段时，**没命中任何时段就按它计** |
| 基础价 · 缓存命中 | 可选。上游返回的缓存命中 tokens 按此价计（DeepSeek `prompt_cache_hit_tokens`、OpenAI `cached_tokens`、Kimi 缓存命中）；留空按输入价 |
| 基础价 · 缓存写入 | 可选。Anthropic `cache_creation_input_tokens`、Kimi 缓存写入按此价计；留空按输入价 |
| 空闲价 · 输入 / 输出 | 可选。**只有打开全局高峰时段、且该模型没配自定义时段时才生效**；留空=不分时 |
| 空闲价 · 缓存命中 | 可选。同上；留空按空闲输入价，再留空按基础输入价 |
| 空闲价 · 缓存写入 | 可选。同上；留空规则同上 |
| **自定义** | 「编辑」按钮打开该模型的单模型计价弹窗（时段 / 分档 / 按次费 / 倍率 / 公式 / 试算，见下）；下方小徽标提示：`时段 3` / `公式` / `按次` / `×1.2`。模型名下方显示 `note` 备注摘要 |

> DeepSeek 就是典型：`deepseek-flash` 高峰输入 ¥2 / 输出 ¥8 / 缓存命中 ¥0.04，空闲时输入 ¥1 / 输出 ¥4 / 缓存命中 ¥0.02。**内置参考价已经为它预填好三段自定义时段**（工作日高峰、工作日其余时间、周末全天），不需要打开全局规则、也不需要手工填右侧空闲价。

**单模型编辑弹窗（「自定义」列 → 编辑）**：只影响这一个模型，保存后写回单价表。分区如下：

| 分区 | 字段 | 用途 |
| --- | --- | --- |
| 基础价 | 输入 / 输出 / 缓存命中 / 缓存写入 | 与表格左侧「基础价 / 峰时」四列同义，弹窗里改也一样 |
| 空闲时段价 | 空闲 · 输入 / 输出 / 缓存命中 / 缓存写入 | **旧版写法**，要打开全局高峰时段才生效；新配置建议直接用下面的「自定义时段价」 |
| 按输入长度分档 | `upTo` + 档内输入/输出/缓存价，可「+ 增加一档」 | 阶梯价（通义千问、豆包）与长上下文加价（Gemini 200K 断点） |
| **自定义时段价** | 卡片式：每段一张卡，含时段名、生效星期、时间窗/指定日期、四档价格与底部「读作」摘要，可「+ 增加一段」 | 每个模型自己的分时规则，见下 |
| **自定义计费（DIY）** | 每次调用固定费用（元）、成本倍率、自定义公式、计费备注 | 见下 |
| 试算 | 输入 / 输出 / 缓存命中 / 缓存写入 tokens + 试算时刻 + 试算按钮 | 不产生真实调用，直接看到成本拆解与命中的时段 |

**自定义时段价（时间与价格都按模型自己定，推荐用法）**：这是 v1.6 起的**主路径**——每个模型自带一张时段表，什么时候贵、什么时候便宜全由这个模型说了算。夜市价 23:00–07:00、周末半价、双十一特价都这样配。

每段以**卡片**呈现（一个时段一张卡，按卡片先后顺序判定），不再挤在一张窄表格里，时间窗再长也能完整看到：

| 卡片上的字段 | 说明 |
| --- | --- |
| 时段名 | 只是标签，会显示在调用日志的成本拆解里（如「夜间特惠」） |
| 生效星期 | `1-5`（周一到周五）、`0,6`（周末，0=周日）、留空 = 每天 |
| 时间窗 / 指定日期 | `09:00-12:00, 14:00-18:00`（可写多个；支持跨零点 `22:00-06:00`；结束写 `24:00` 表示到当天结束）；只写 `2026-11-11` 则当天整日生效 |
| 输入 / 输出 / 缓存命中 / 缓存写入 | 该时段的单价（元 / 百万 tokens），留空沿用基础价 |
| 底部「读作」 | 实时把你填的内容翻译成一句话，例如「每周 周一~周五 · 09:00-12:00 14:00-18:00 · 价格全部留空 → 跟随基础价」，填错顺序或漏填时间窗一眼就能看出来 |

判定规则：

1. **写日期的段优先**（大促、节假日特价总能盖住常规时段），其余段**从上往下先命中先用**——把更具体的段放上面。
2. 都不命中 → 按基础价（`in` / `out`）。
3. **配了自定义时段，这个模型就完全按自己的时段表算**，不再看「空闲时段价 + 全局高峰规则」；想回到旧行为，把时段卡删空并勾上全局规则。
4. 时间一律按北京时间（UTC+8）判断，与服务器时区无关。
5. 段内价格可以留空（= 沿用基础价）。**高峰段建议留空**：以后改基础价，高峰价自动跟着变，不用两处维护。

> 内置参考价里 DeepSeek 两个模型已经配好现成的三段，可直接照抄或微调：
>
> | 时段名 | 生效星期 | 时间窗 | 价格 |
> | --- | --- | --- | --- |
> | 高峰·工作日 | `1-5` | `09:00-12:00, 14:00-18:00` | 留空（= 基础价） |
> | 空闲·工作日 | `1-5` | `00:00-09:00, 12:00-14:00, 18:00-24:00` | 谷时价 |
> | 空闲·周末 | `0,6` | `00:00-24:00` | 谷时价 |
>
> 法定节假日（如春节）当天平台不会自动识别，需要时加一段「按日期」的时段，填 `2026-11-11` 这样的日期即可整日生效。

DIY 三个字段（可任选，也可组合）：

- **每次调用固定费用 `perCall`**：按次计费的模型（图像、语音、检索类）用它，叠加在 token 费用上。
- **成本倍率 `multiplier`**：`1.2` = 上浮 20%（代理商加价）、`0.8` = 八折、`0` = 内部免费。对「(token 费用 + 按次费)」整体相乘。
- **自定义公式 `formula`**：完全自定义金额（元），**公式结果直接替代基础 token 费用**，之后再叠加上面的按次费与倍率。
  - 可用变量：`prompt` `completion` `cacheHit` `cacheWrite` `miss` `inPrice` `outPrice` `cacheInPrice` `cacheWritePrice` `base` `calls`。
  - 只支持 `+ - * /` 和括号，不支持函数与 `eval`；保存时校验语法，写错直接报错并拒绝保存。
  - 例：`base * 1.2 + 0.001`（加价 20% 再收 1 厘）、`prompt * 0.000002 + completion * 0.000008`。
- **计费备注 `note`**：写「官方 2026-11 调价」「代理商加价 10%」这类说明，显示在单价表模型名下方。

> 拆解结果会随明细落盘（`costDetail`），在调用日志详情里能看到本次用的是哪条公式、倍率多少、按次费多少。完整口径与算例见 [计费与成本核算](计费与成本核算.md) 第 3.5 节。

**高级定价（JSON）**：单价表下方的卡片可编辑完整定价对象，用于配置 `tiers`（按输入长度分档，如通义千问阶梯价、Gemini 200K 断点）等进阶字段。保存时以「主表」值为准合并，高级字段（`tiers`、未在表格中出现的字段）保留。

**计费口径速记**（完整说明与算例见 [计费与成本核算](计费与成本核算.md)）：

- 价格随官方调整，以各厂商账单为准；内置参考价核对日期见计费手册。
- 成本按**每次请求发生时刻**所处时段计价并随明细落盘，事后调整单价不影响历史记录。
- 一个模型的时间维度只会有一种生效：**自定义时段（`periods`）> 空闲时段价（`idle`）+ 全局高峰规则**；全局规则默认关闭，所以不配 `periods` 又不打开开关的模型就是「不分时」。按输入长度分档（`tiers`）仍然优先于分时。
- 未配置单价的模型成本记 0，前端显示「未定价」。

### 3.5 调用日志

列表每行：时间、员工（含部门）、**模型 + 请求内容摘要**、渠道、Token（总量 + 入/出）、**成本**、耗时、状态，最后一列「详情」。

| 状态 | 含义 |
| --- | --- |
| 成功 | 上游正常返回 |
| 配额拦截 | 被配额检查拦下（429），`error` 字段写明是哪个维度、员工还是部门 |
| 失败 | 模型越权（403）、上游错误、鉴权失败等，`error` 写明原因 |

**筛选与搜索**：顶部状态下拉 + 关键词搜索框（搜员工名、模型、错误信息、最后一次提问）；接口另支持按员工 / 部门 / 模型过滤（见 [API 参考](API参考.md#26-调用日志)）。

**详情弹窗**（点行尾「详情」）把一次请求完整摊开：

| 区域 | 内容 |
| --- | --- |
| 状态头 | 员工 / 部门 / 模型 / 渠道 / 状态 / 成本（大号字） |
| 元信息 | 时间、耗时、Token 入/出、缓存命中/写入、**Token 来源**（`上游返回` / `估算`）、上游模型名、渠道尝试次数、请求 ID |
| 请求参数 | `temperature` `top_p` `max_tokens` `stream` `n` `tools` `response_format` 等（只列实际传了的） |
| 输入内容 | 按 role 着色的消息气泡（system / user / assistant / tool），超长时标「已截断」 |
| 输出内容 | 模型回复正文 + `finish_reason`；流式请求显示拼接后的完整文本 |
| 成本拆解 | token 基础费用 → 自定义公式 → 按次费 → 倍率 → 合计，附本次单价与 Token 构成 |
| 渠道尝试 | 每个渠道一行：渠道名、成功/失败、HTTP 状态、错误、耗时；failover 时能看出切了几次 |

> 详情走 `GET /api/logs/:id`，要服务端也是新版本。若点「详情」提示**「接口不存在」**，是典型的「改了代码没重启」：静态文件每次从磁盘读、已经是新版界面，而进程里还是旧路由。页面底部会同时出现「服务端还在运行旧代码」提示条，重启后即恢复（`pkill -f "node server.js" && npm start`）。
>
> 策略为 `off` 时，详情弹窗仍能打开，但「输入内容 / 输出内容」显示「未留存」，其余元信息、成本拆解、渠道尝试链照常有。
>
> 所有上游渠道都停用时，网关返回**内置模拟响应**——这类记录同样会留下输出正文，并在「渠道尝试」里显示一条 `mock`，方便在没接真实 Key 时先把日志流程走通。

**内容留存策略**（系统设置 → 调用日志内容）：

| 策略 | 存什么 | 适合 |
| --- | --- | --- |
| 关闭 `off` | 只存 token / 成本 / 状态，不落正文 | 合规上不允许落地正文，或库体积敏感 |
| 摘要 `summary`（默认） | 按「摘要最大长度」截断（默认 2000 字符，可调 200–20000） | 日常排障 |
| 完整 `full` | 尽量保留全文（单条上限 20000 字符） | 短期深度排障，注意 `db.json` 体积 |

- 超长时**从最旧的消息开始丢**，优先保留最近几轮；首条 system 提示被挤掉时会补回一条 ≤400 字的摘要。
- 日志正文里的 `sk-` 密钥、`Bearer` 值、URL 上的 `?key=` / `api_key=` / `token=` 参数会自动打码（`sk-ai***`），不会二次泄漏。
- 列表接口只回摘要（`preview` 前 80 字 + `hasContent`），正文只在详情接口返回，避免一次拉几百条把浏览器拖死。
- 明细保留最近 5000 条；日报/月报聚合保留 120 天。日志里同时记录 `promptTokens`、`completionTokens`、`cacheTokens`、`cacheWriteTokens`、`cost`，可直接用于对账。


### 3.6 接入文档

自动填充当前平台地址与所选员工的完整 Key，并给出 curl / Python / Node 三种示例，可直接复制发给同事。页面上可切换员工，避免把某个人的 Key 当通用 Key 发出去。

### 3.7 扩展插件（批量导入组织架构）

两级结构：插件列表点卡片 → 进入该插件的配置页（地址形如 `#/plugins/feishu`，可收藏）。

| 插件 | 需要填 | 凭证在哪拿 |
| --- | --- | --- |
| 飞书通讯录 | App ID、App Secret（可选 API 域名，海外 Lark 换 `https://open.larksuite.com`） | 飞书开放平台 → 开发者后台 → 企业自建应用；需开通「获取部门基础信息」「获取成员基础信息」权限 |
| 企业微信通讯录 | 企业 ID、通讯录 Secret | 企微管理后台 → 管理工具 → 通讯录同步 → 开启并查看 Secret |
| 文本 / CSV 导入 | 粘贴文本即可 | 无。每行 `姓名,邮箱,部门`，邮箱可省略，首行若为「姓名」自动当表头 |

每个插件三个按钮：**保存配置**、**连接测试**（报出能拉到几个部门/几个人）、**立即同步**。

**同步规则（幂等，可反复执行）**：

1. 部门按**名称**合并：已存在的不动，新的自动创建（额度为 0，同步完自己分配）。
2. 员工按**邮箱**匹配，其次**同名**：已有员工只更新归属部门，**不覆盖你已设置的额度、密钥与模型白名单**。
3. 新员工自动签发虚拟 Key，去「员工管理」复制发给他。
4. 飞书侧的离职成员自动跳过。

自行接入钉钉 / LDAP / HR 系统见 [插件开发手册](插件开发手册.md)。

### 3.8 系统设置

按界面顺序分七块：

1. **基础设置**：平台名称、额度用尽策略（当前推荐「直接拒绝 429」）、「没有可用渠道时返回内置模拟响应」开关。
2. **调用日志内容**：留存策略（关闭 / 摘要 / 完整）+ 摘要最大长度 + 「流式请求向上游索取真实用量」开关。决定调用日志里能不能看到输入输出正文，取舍见 [3.5](#35-调用日志)。正文中的密钥会自动打码。
   - 「流式请求向上游索取真实用量」默认**开启**：网关会给流式请求补 `stream_options.include_usage`，让上游在流末尾返回真实 token 数。关掉后上游通常不返回用量，网关只能按文本估算，**和厂商账单会有偏差**，除非有客户端兼容性顾虑，否则不要关。
3. **用量告警（全局默认）**：机器人 Webhook + 启用开关 + 默认阈值（默认 `80, 100`）+ 默认监控维度（日 / 月 Token）+「发送测试消息」。
   - 这是**兜底配置**：部门、员工没单独配置时都用这里的通道与阈值。
   - 继承顺序：**员工 Webhook → 所属部门 Webhook → 全局机器人**；阈值与维度同理。给每个部门单独建群，就能做到「谁超了只通知谁」。
   - 卡片底部会列出「已配置独立通道」的部门 / 员工，一眼看出谁没用全局机器人。
   - 支持飞书自定义机器人与企业微信群机器人，按 URL 自动识别格式。详见 [告警与运维手册](告警与运维手册.md#1-用量告警)。
4. **修改管理员密码**：需校验原密码，新密码至少 6 位。
5. **最近告警**：最近 200 条发送记录（时间 / 对象 / 触发条件 / 用量 / 通道 / 结果），失败会显示原因片段。点过「发送测试消息」也会留一条标「测试」的记录——全局那条对象显示「全局 · 全局默认」，可用来确认通道是否通。
6. **数据管理 → 清空业务数据**：清掉部门/员工/日志/统计/告警记录，**保留上游渠道与模型单价、平台设置、插件配置**；清空前自动备份到 `data/db-backup-<时间戳>.json`，清空后重启也不会再灌演示数据。
7. **数据备份 → 下载脱敏配置**：导出的 JSON 不含任何密钥与密码，适合排查问题或迁移结构。

> `data/db.json` 就是全部数据，拷走即完整备份。开了日志正文后它会明显变大（单条最多 20000 字符 × 5000 条），体积敏感就把留存策略设为「摘要」并调小最大长度。

## 4. 员工侧指引（可直接转发）

1. 找管理员拿两样东西：**接入地址**（如 `http://内网IP:8787/v1`）和你的**专属 Key**（`sk-ai-` 开头）。这是平台签发的虚拟 Key，不是任何上游服务的真实密钥。
2. 原有 OpenAI SDK 只改 `base_url` 和 `api_key` 两行就能用，支持流式输出。常用客户端（Dify / Cherry Studio 等）在「自定义 OpenAI 接口」里填同样两样。
3. 只能调用管理员给你的模型范围（部门或个人的白名单）。调用范围外模型会收到 **403**：

   ```json
   {
     "error": {
       "type": "model_not_allowed",
       "code": "model_not_allowed",
       "message": "没有权限使用模型「gpt-5.5」（部门策略限制，允许：gpt-4o-mini、deepseek*）"
     }
   }
   ```

4. 额度用完会收到 429，返回体里写明了是**你自己的额度**还是**部门池**用完、是哪个维度（日/月/RPM/并发），找管理员调整即可。
5. Key 泄露就找管理员重置，重置后旧 Key 立即失效。

示例：

```bash
curl http://<平台地址>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-ai-你的虚拟Key" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"你好"}]}'
```

## 5. 常见问题

| 问题 | 处理 |
| --- | --- |
| 员工反馈 429 | 看返回体里的 `scope`（employee/department）和 `dimension`，到对应页面调额度即可 |
| 员工反馈 403 `model_not_allowed` | 到员工编辑 → 特例 → 「允许的模型」或部门 → 「模型白名单」里补上该模型（支持 `xxx*`） |
| 想临时给某人提额 | 员工编辑 → 开特例 → 填需要的值 → 设过期时间，到期自动回落 |
| 想临时给某人开某个模型 | 员工编辑 → 开特例 → 「允许的模型」填该模型（会整体覆盖部门白名单，需要把其他要用的模型一起写上） |
| 员工离职 | 直接删除员工，或先停用再删；他的 Key 立即失效，其他人不受影响 |
| 换上游密钥 | 渠道编辑里填新 Key，员工侧无感知 |
| 成本一直是 0 | 该模型没配单价；到「上游渠道 → 模型单价」填输入/输出价，只对新产生的用量生效 |
| 空闲价没生效 | v1.6 起全局高峰规则**默认关闭**，只填「空闲价」不会分时；改用弹窗里的「自定义时段价」，或在单价页勾上「启用全局高峰时段（兜底）」 |
| 分时全部按基础价算 | 该模型既没配自定义时段，也没配空闲价 + 全局规则；看卡片标题标签「按模型时段计价 · N 个模型已配」，给模型加时段，或「载入官方参考价」恢复 DeepSeek 的预置三段 |
| 自定义时段没生效 | 用弹窗里的「试算时刻」按目标时间试算，看是否命中；再检查生效星期是否包含当天、时间窗是否写对（`09:00-12:00`）、是否被更前面的日期段抢走；配了时段后就不再走全局高峰规则 |
| 配了公式但算出来的钱不对 | 详情弹窗的成本拆解里能看到「公式结果 / 按次费 / 倍率」各自多少；公式结果**替代** token 费用后再乘倍率，写错时 `costDetail.formulaError` 会有提示并回落到基础价 |
| 保存单价提示「公式有误」 | 公式只支持 `+ - * / ( )` 与变量名（`prompt` `completion` `cacheHit` `cacheWrite` `miss` `inPrice` `outPrice` `cacheInPrice` `cacheWritePrice` `base` `calls`），不能写函数、百分号或中文符号 |
| 调用日志看不到输入输出 | 系统设置 → 调用日志内容 的留存策略是「关闭」；改成「摘要」或「完整」后只对**新产生**的记录生效，旧记录不会补 |
| 点「详情」提示**「接口不存在」** | 服务端进程还在跑更新前的代码（静态页每次从磁盘读，已是最新）。页面底部会有「服务端还在运行旧代码」提示条；重启即可：`pkill -f "node server.js" && npm start`。核对版本：侧栏底部「前端 v…」与 `curl -s localhost:8787/healthz` 返回的 `version` 应一致 |
| 日志正文只显示一部分 | 超过「摘要最大长度」被截断（弹窗会标「已截断」）；调大长度或改成「完整」策略 |
| 用量告警没收到 | 先在该对象的编辑弹窗点「发送测试消息」验证通道；同一对象同一维度同一阈值每个统计周期只推一次；额度为 0（不限）不告警；到「系统设置 → 最近告警」看有没有发送失败记录 |
| 流式输出卡住 | 检查 Nginx 是否关了 `proxy_buffering` |
| 数据丢了 | 恢复最近一次 `db.json` 备份；清空操作本身也会先自动备份 |
| 想多实例部署 | 暂不支持：计数器在内存，只能单实例；横向扩展需把 `lib/store.js` 计数器换 Redis |

## 6. 安全须知

- 管理台只有一道管理员密码，务必改掉默认密码，并限制管理台的访问来源（内网 / VPN）。
- 虚拟 Key 在服务端明文存储（为了管理员能随时复制分发）。若安全要求更高，可改为只存哈希——代价是平台自己也看不到完整 Key，只能「重置后重新分发」。
- 插件凭证（飞书 Secret、企微 Secret）、上游真实 Key、告警 Webhook 全部随 `db.json` 存储，注意该文件目录权限（建议 `700`）。
- 「下载脱敏配置」导出的是脱敏结果，不要把 `data/db.json` 原文发给外部。
